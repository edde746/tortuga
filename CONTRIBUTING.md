# Contributing to Tortuga

Tortuga is one repository: a Kotlin Multiplatform core in `shared/`, a Compose UI for Android, Android TV, Windows
and Linux, SwiftUI apps for iOS, iPadOS, macOS and tvOS, libmpv from
[edde746/mpv-build](https://github.com/edde746/mpv-build) on every platform, and a Ktor sync server.
[ARCHITECTURE.md](ARCHITECTURE.md) explains how the parts fit together.

## Prerequisites

- **A JDK to run Gradle**, 17 or newer. Gradle downloads the toolchains the modules build with when the machine lacks
  them: JDK 27 for `shared`, `dev`, `ui-compose` and the server, JDK 25 for the desktop modules (JetBrains Runtime 25
  on Linux).
- **The Android SDK** with platform 37, found through `ANDROID_HOME` or `local.properties`. Without one, pass
  `-Ptortuga.android=false` (or set `TORTUGA_ANDROID=false`): Gradle then leaves out the Android modules and the
  Android targets of `shared` and `ui-compose`.
- **For the Apple apps:** an Apple silicon Mac (Kotlin/Native and the apps build for arm64 only), Xcode, and XcodeGen
  2.46.0, which `tools/install_xcodegen.sh <dir>` downloads into `<dir>`, checks by its sha256 and prints the path
  of. An older XcodeGen refuses to generate the project (`minimumXcodeGenVersion` in `apple/project.yml`).
- **Docker** for `:server:test` (Postgres in Testcontainers) and for running the server.
- **Bun 1.4.2** for the website.
- **Python 3** for `store/check.py` and the media server and test servers in `tools/media/`.
- **For `tools/brand/verify.sh`:** Xcode, the Android SDK's build-tools 37.0.0 and platform android-37.0, and
  ImageMagick 7.
- **For the test media:** ffmpeg with libx264, libx265 and libsvtav1, MKVToolNix, dovi_tool, uv and ImageMagick.

### libmpv

libmpv arrives with the build; there is no manual step. `mpv-build.lock.json` records, per platform, the mpv-build
commit it is pinned to:

- Android: Gradle fetches mpv-build's `mpv-android` AAR (libmpv, FFmpeg and the JNI glue) from mpv-build's GitHub
  release. `mpv-build.lock.json` names it, and `gradle/verification-metadata.xml` checks its sha256.
- Windows and Linux: build-logic's `tortuga.mpv-artifacts` plugin downloads the pinned libmpv tarballs from
  `mpv-build.lock.json` and checks their sha256.
- Apple: Swift Package Manager fetches MPVKit (libmpv, FFmpeg and libass as XCFrameworks) from mpv-build at the
  revision in `apple/project.yml`, which must equal the lock's apple commit (the `tortuga.mpv-artifacts` plugin fails
  the Gradle build when they differ).

The platforms are pinned apart for now. Android must stay below mpv-build's pull request #14 (069cc95f5): from its
patch 0142 on, subtitles can show a refresh early on MediaTek Android TV boxes, as mpv-build's README warns. Linux and
Windows stay on Android's commit; Apple is ahead, on the release whose libplacebo renders the video shaders on its
video output. `tools/set_native_revision.sh --only <android|linux|windows|apple> <commit>` moves one platform, and
`tools/set_native_revision.sh <commit|latest>` moves every pin site together; once mpv-build fixes the subtitle
timing, that brings every platform back to one revision. Each artefact carries the licence texts
of the components linked into it, which every app ships and About shows; a pin whose artefacts lack them fails the
builds ([licenses/README.md](licenses/README.md#mpv-builds-texts)).

## Build and test

Run these from the repository root unless a section says otherwise.

### Gradle

```sh
./gradlew :build-logic:test :shared:jvmTest :dev:jvmTest :ui-compose:jvmTest :mpv-jvm:test :app-desktop:test :app-android:assembleDebug --continue
```

It covers what most changes touch: the strings generator's tests and the translation coverage test
(`:build-logic:test`, which the root `check` doesn't reach), the shared core's and `dev`'s JVM tests, the Compose UI
tests, the desktop engine's tests that need no libmpv, the desktop app's tests and the Android debug APK.
`:ui-compose:jvmTest` needs a display: on a headless Linux machine AWT throws `HeadlessException`. `:shared:jvmTest`
leaves out the sync and watch-together end-to-end tests, which need a running server or relay. On a Mac, add
`:shared:compileTestKotlinIosSimulatorArm64 :dev:compileTestKotlinIosSimulatorArm64`: Kotlin/Native rejects some
common code the JVM compiles (a call deprecated as an error there only, such as `String(CharArray)`).

| Command | What it does |
|---|---|
| `./gradlew :shared:verifyCommonMainTortugaDatabaseMigration` | checks the SQLDelight migrations against the schema; run it after a change in `shared/src/commonMain/sqldelight/` |
| `./gradlew :server:test` | the server's tests against Postgres in Testcontainers, with fake sign-in providers and trackers; Docker must be running |
| `./gradlew -Ptortuga.android=false :app-desktop:test` | the desktop app's tests on a machine without an Android SDK |
| `./gradlew :app-android:assembleDebug` | the debug APK, in `android/app/build/outputs/apk/debug/`; it installs as `com.edde746.tortuga.dev` ("Tortuga Dev") beside a release build |
| `./gradlew :app-desktop:run` | starts the desktop app on Windows or Linux; Linux needs a Wayland session |
| `./gradlew :app-desktop:createDistributable` | the desktop app image, in `desktop/app/build/compose/binaries/main/app/` |
| `./gradlew :shared:iosSimulatorArm64Test :shared:tvosSimulatorArm64Test :dev:iosSimulatorArm64Test` | the common tests on the iOS and tvOS simulators' runtimes (Apple silicon Mac); in a checkout under `~/Documents` the Keychain tests fail with OSStatus -34018, since macOS keeps the simulator's `securityd` from reading the test binary's entitlements there |

End-to-end runs of the server and of the shared sync client against it are in
[server/README.md](server/README.md), Development.

### Apple

```sh
xcodegen=$(tools/install_xcodegen.sh /tmp/tortuga-tools)
cd apple && "$xcodegen" generate
xcodebuild -project Tortuga.xcodeproj -scheme Tortuga-iOS -configuration Debug -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project Tortuga.xcodeproj -scheme Tortuga-tvOS -configuration Debug -destination 'generic/platform=tvOS Simulator' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project Tortuga.xcodeproj -scheme Tortuga-macOS -configuration Debug -destination 'platform=macOS,arch=arm64' CODE_SIGNING_ALLOWED=NO build
```

`apple/Tortuga.xcodeproj` is generated and not committed: change `apple/project.yml` and generate again. Each build
runs Gradle first (the "Build TortugaKit (Kotlin)" phase) to link the shared Kotlin framework for that platform:
Debug links `:dev`'s, which carries the development session, and Release links `:shared`'s. The iPhone, iPad and
Apple TV targets sign with a team for real devices; to run on your own device, set `DEVELOPMENT_TEAM` to your team.

### Website, store listings, icons

```sh
cd website && bun install --frozen-lockfile && bun run check && bun run build
```

```sh
python3 store/check.py
tools/brand/verify.sh
```

[website/README.md](website/README.md) covers the site's development server and deploys. `store/check.py` checks
every store field in every locale against its store's limit and the listing rules, and the demo addon's files; run
it after any change in `store/`. `tools/brand/verify.sh` compiles the icons and banners that `tools/brand/generate.sh`
makes with each platform's toolchain; run it after a change in `tools/brand/`.

## Strings

Every string the apps show comes from `shared/i18n/`: `en.i18n.json` is the base, and `ar`, `cs`, `de`, `es`, `fr`,
`hi`, `id`, `it`, `ja`, `ko`, `nl`, `pl`, `pt-BR`, `ro`, `ru`, `sv`, `th`, `tr`, `uk` and `vi` are the 20 translations.

- Nested objects group keys. `${name}` is a parameter. An object with CLDR plural keys (`zero`, `one`, `two`, `few`,
  `many`, `other`) is a plural, and `${n}` is its count.
- build-logic's `tortuga.strings` plugin generates Kotlin accessors (`T`) into `shared` at build time, so both UIs
  read the same strings; the Apple apps' Info.plist purpose strings are generated from the same files.
- English defines every key, its shape and its parameters. A translation may not add a key or change one's shape or
  parameters: the generator stops the build.
- A key that a translation lacks, or leaves empty, shows in English at run time. `TranslationCoverageTest` (in
  `:build-logic:test`) fails on every English key a translation lacks, so a new string goes into all 21 files in the
  same change.
- Text built from data (durations, `S1E2`, sizes, relative dates, stream badges) is formatted in `shared`, not in a
  view.

## Code and tests

- Keep it minimal and boring: no abstraction before its third caller, no wrapper around a single call, no
  compatibility shims. Delete what your change leaves unused in the same change.
- Errors fail loudly at the boundary. No empty `catch`.
- The shared core decides what shows when. A Compose or SwiftUI view renders a store's state and sends intents.
- A change to `shared`'s API comes with every UI that uses it: the Compose apps and the Apple apps both build.
- Configured addon URLs and stream URLs can carry keys to other services. Redact them in logs and test fixtures.
- A change that bundles a new component (a library, a font, a native library) lists it with its licence in
  `shared/src/commonMain/kotlin/com/edde746/tortuga/presentation/settings/ThirdPartyNotices.kt`, which the About
  screen shows, for each platform that ships it, and adds its licence texts to `licenses/` (`licenses/README.md`).
  `ThirdPartyNoticesCoverageTest` (`:shared:jvmTest`) fails on a Gradle module the Android release build, the desktop
  app or Apple's framework resolves, or a Swift package an Apple app links, whose project has no notice there or no
  prefix in the test's map; `ThirdPartyLicenseFilesTest` fails on a notice whose texts its app doesn't ship.
- A test defends an observable contract: behaviour, boundaries, transitions. No tests of markup, wiring or defaults.
- Comments state what the code does and why, as facts about the code.

## UI tests

The Compose UI tests run in `:ui-compose:jvmTest`. The Android device tests (`shared/src/androidDeviceTest`,
`android/mpv/src/androidTest`) run on a connected device or emulator.

The Apple UI tests (`apple/TortugaUITests/`, the `Tortuga-*-UITests` targets) drive a Debug build in a development
session against the media server and two test servers in `tools/media/`:

1. `tools/media/make-matrix.sh` builds the test media into `tools/media/out/matrix/`; `make-live.sh` and
   `make-error-video.sh` add the live channel and the error videos the player tests play.
2. `python3 tools/media/serve.py 8765` serves `tools/media/out/` with Range support.
3. `python3 tools/media/test_addon.py --media http://127.0.0.1:8765/matrix --search --pages --live` is the test
   addon, on port 8766, its manifest at `/manifest.json`.
4. `python3 tools/media/test_trackers.py --approve-after 12` is the fake Trakt, on port 8772.

The test runner reads these variables; `xcodebuild test` passes each as `TEST_RUNNER_<name>`
(`TEST_RUNNER_TORTUGA_ADDON=http://127.0.0.1:8766/manifest.json`):

| Variable | Value |
|---|---|
| `TORTUGA_ADDON` | the test addon's manifest URL; required by every test that installs the test addon |
| `TORTUGA_TRACKERS` | the fake Trakt's base URL; required by the tests that connect a tracker |
| `TORTUGA_LANGUAGE` | the app's languages, most preferred first, comma-separated; default `en` |
| `TORTUGA_MUTE` | `1` starts the player muted |
| `TORTUGA_DEV_SETTINGS` | device settings for every launch, `key=value` separated by spaces |

Tests that read `TORTUGA_SERVER`, `TORTUGA_EXCHANGE` or `TORTUGA_WATCH_RELAY` also need a running sync server, a
watch-together relay, or a process on the host that acts on the files the test writes (pointer clicks and drags on
the Mac, codes for a second device). Without them those tests fail at once and say which variable is missing.

## Commits

Conventional Commits: `type(scope): lowercase imperative summary`, at most 72 characters, no period. The scope is the
area changed (`shared`, `compose`, `apple`, `server`, `i18n`, `website`, `store`, `build`, ...). Examples from the
history: `fix(compose): hyphenate words wider than a card or tile`, `feat(apple): rate a title from detail's ratings
row`.

## Pull requests

- One change per pull request, branched from `main`, titled like a commit.
- Run the checks for what you changed: the Gradle command under Build and test for Kotlin (and `:server:test` for
  `server/`), the three Apple builds when `shared` or `apple/` changed, `bun run check` and `bun run build` for the
  website, `python3 store/check.py` for `store/`, `tools/brand/verify.sh` for `tools/brand/`.
  `.github/workflows/ci.yml` holds the same Gradle tests for Linux and Windows runners, the Kotlin/Native tests and
  the three Apple builds for macOS, and the website's check and build; it runs on every push to `main` and every pull
  request, and a failing job keeps its test reports as an artifact.
- A behaviour change comes with a test that fails without it.
- A UI change comes with screenshots of every platform it touches.
- New strings come in all 21 languages.
